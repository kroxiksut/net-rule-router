# Сборка NetRuleRouter для Windows

[English](../en/packaging-windows.md) · **Русский**

`scripts/package-windows.ps1` превращает рабочую копию в папку, которая
запускается на чистой машине с Windows: без Qt, без Rust, без репозитория и без
установщика. Папку копируют на целевой компьютер и запускают
`NetRuleRouter.exe`.

По запросу тот же запуск собирает из этой папки ещё два установщика, EXE и MSI.
Они кладут программу в Program Files, ставят фоновую службу
и так же чисто всё удаляют. См. [Установщики](#установщики).

## Как запускать

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\package-windows.ps1 -Zip
```

Пакет появится в `C:\temp\NetRuleRouter\dist\NetRuleRouter`, а `-Zip` положит
рядом архив.

| Параметр | Что делает |
|---|---|
| `-OutputRoot <путь>` | Где создать папку пакета. По умолчанию `C:\temp\NetRuleRouter\dist`. |
| `-SkipBuild` | Упаковать уже собранные релизные бинарники, не пересобирая. |
| `-Arch x64` / `-Arch arm64` | Для какого процессора пакет. По умолчанию `x64`. См. [Пакеты ARM64](#пакеты-arm64). |
| `-QtBin <путь>` | Каталог `bin` набора Qt для `-Arch`. По умолчанию берётся набор, которым собран Qt-хост; другой набор отвергается. |
| `-Full` | Выложить полный рантайм Qt вместо урезанного. |
| `-Zip` | Дополнительно собрать `NetRuleRouter-windows-<arch>-<версия>-portable.zip` и архив символов этой сборки. |
| `-Installers` | Дополнительно собрать EXE-установщик и MSI, а также файл контрольных сумм всего, что сделал запуск. |
| `-NoSymbols` | Не собирать архив символов — для пробной сборки. У выпуска он есть всегда. |
| `-Exe` / `-Msi` | Собрать только один из двух установщиков. |
| `-Headless` | Собрать без окна и значка в трее: служба, `nrr-cli` и `nrr-tui` — для серверов и Windows без рабочего стола. Папка — `NetRuleRouter-headless`, в имени каждого артефакта после версии стоит `-headless` (`...-<версия>-headless-portable.zip`). |
| `-Force` | Заменить папку, оставшуюся от прошлого запуска. |

Чужую папку скрипт не удалит: перед копированием он кладёт метку
`.nrr-package`, и `-Force` очищает только каталог с этой меткой.

## Что оказывается в пакете

```
NetRuleRouter\
  NetRuleRouter.exe     запускать это
  README.txt            заметки для пользователя (английский)
  README.ru.txt         те же заметки по-русски
  build-info.json       версия, ревизия, время сборки
  <трей, служба, консоль, терминальный интерфейс, хост Qt, рантайм Qt, wintun.dll>
  qml\                  модули самого Qt
  apps\desktop\qml\     интерфейс программы
  locales\  presets\  configs\  assets\  scripts\
  licenses\            тексты лицензий: продукта, Wintun и (в полном пакете) Qt
  docs\                эти страницы в виде офлайн-HTML, docs\<язык>\index.html
```

Офлайн-страницы открывает пункт «Справка > Документация». Если страница
ссылается на то, чего нет, сборка останавливается.

Две детали этой раскладки — не оформление, а необходимость:

- **Интерфейс сохраняет путь `apps\desktop\qml`.** QML адресует значки
  относительно себя (`../../../assets/icons/...`), поэтому в более мелком
  каталоге не находится ни один значок. Заодно интерфейс не сталкивается с
  `qml\`, который Qt занимает под свои модули.
- **Бинарники лежат в корне пакета.** Windows ищет библиотеку сначала в
  каталоге самой программы — благодаря этому рантайм Qt и библиотеки
  Visual C++ путешествуют вместе с ней.

## Зачем нужен штамп сборки

В каждом пакете лежит `build-info.json`:

```json
{
  "product": "NetRuleRouter",
  "version": "0.1.0-alpha.1",
  "commit": "19670e8",
  "commit_date": "2026-08-07T22:37:22+08:00",
  "uncommitted": true,
  "built_at_utc": "2026-08-10T14:17:40Z",
  "profile": "release",
  "platform": "windows-x64",
  "qt_version": "6.11.1",
  "qt_runtime": "trimmed"
}
```

Поле `uncommitted` говорит, были ли в рабочей копии незакоммиченные правки в
момент сборки. Если там `true`, одна лишь ревизия этот код не опознаёт — это
стоит указывать в отчёте о проблеме. Те же версия и ревизия печатаются в начале
обоих README. В именах файлов только версия, поэтому у двух локальных сборок
одной версии имена совпадают: различить их можно по `build-info.json`.

## Установщики

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\package-windows.ps1 -Zip -Installers
```

Всё появляется рядом с папкой пакета; процессор (`x64` или `arm64`) и версия
есть в каждом имени:

| Файл | Что это |
|---|---|
| `NetRuleRouter-windows-<arch>-<версия>-portable.zip` | Переносимая сборка (`-Zip`): распаковать и запустить, ничего не устанавливая. |
| `NetRuleRouter-windows-<arch>-<версия>-setup.exe` | EXE-установщик, на русском и английском. |
| `NetRuleRouter-windows-<arch>-<версия>.msi` | MSI для систем развёртывания и `msiexec`, на русском и английском: язык следует языку интерфейса Windows. |
| `NetRuleRouter-windows-<arch>-<версия>-symbols.zip` | Отладочные символы этой сборки. Для запуска и установки не нужны; см. [Отладочные символы](#отладочные-символы). |
| `NetRuleRouter-windows-<arch>-<версия>-SHA256SUMS.txt` | Контрольные суммы SHA-256 всех файлов выше; проверяются `sha256sum -c`. |

Установщик запускается только на том процессоре, для которого собран: `x64` —
на Windows x64, `arm64` — на Windows на ARM.

### Отладочные символы

В пакете и в обоих установщиках нет отладочных символов, поэтому они примерно
вдвое меньше. Символы той же сборки лежат отдельно, в `-symbols.zip`: он
появляется вместе с любым архивом или установщиком (пробная сборка может
пропустить его ключом `-NoSymbols`) и прикладывается к каждому
выпуску, и для x64, и для ARM64. Пользователю он не нужен никогда: он для
разработчиков, разбирающих сбой именно этой сборки. Символы другой сборки не
подходят. Символы для Linux тоже скачиваются отдельно, см.
[Отладочные символы](packaging-linux.md#отладочные-символы).

Что делают оба установщика:

- Перед установкой показывают пользовательское соглашение NetRuleRouter на
  языке установщика: его нужно прочитать и принять. Учётную запись Windows,
  которая приняла его в установщике, программа при первом запуске больше не
  спрашивает. Каждую другую учётную запись она попросит принять соглашение при
  её первом запуске: согласие при установке не действует за других
  пользователей компьютера. Если установщик EXE подтвердили паролем другого
  администратора, соглашение считается принятым этим администратором, и того,
  кто запустил установку, программа спросит при первом запуске. Новая версия
  с изменённым соглашением спросит всех заново.
- Просят права администратора и по умолчанию ставят программу в
  `C:\Program Files\NetRuleRouter`. Можно выбрать другую папку, но только
  внутри Program Files: служба работает с правами системы, поэтому запускается
  только из папки, которую обычный пользователь изменить не может. Папку в
  другом месте установщик не примет и скажет почему.
- Окно, значок в трее, фоновая служба и консоль (`nrr-cli`) ставятся всегда:
  удаление и восстановление программы выполняются через консоль.
  Терминальный интерфейс (`nrr-tui`) отмечен по умолчанию, от него можно
  отказаться.
- Офлайн-документация (эти страницы в виде HTML, их открывает пункт
  «Справка > Документация» без подключения к интернету) отмечена по
  умолчанию, от неё можно отказаться; тогда программа открывает страницы в
  интернете.
- Добавляют NetRuleRouter в меню «Пуск», а по желанию и на рабочий стол (по
  умолчанию не отмечено). Спрашивают, для кого эти ярлыки и запись в PATH
  (см. ниже): для всех пользователей компьютера (по умолчанию) или только для
  вас; сама программа и её служба в любом случае ставятся на весь компьютер.
- По желанию (по умолчанию не отмечено) добавляют `nrr-cli` и `nrr-tui` в
  PATH, чтобы их можно было запускать из любого нового терминала. Добавляются
  только эти две команды, а не папка программы.
- Последняя страница предлагает запустить NetRuleRouter. Программа
  запускается от вашего имени, а не с правами администратора установщика.
- При обновлении и удалении установщик сам закрывает окно, значок в трее и
  терминальные инструменты во всех вошедших учётных записях; ничего не нужно
  закрывать вручную.
- Ставят фоновую службу и запускают её. Служба стартует вместе с Windows; если
  раньше она была настроена запускаться вместе с программой, этот выбор
  сохраняется.
- Установка новой сборки поверх старой останавливает службу, заменяет файлы и
  снова её запускает. Настройки, правила и журнал аудита сохраняются.

### Удаление установленной копии

Удаление всегда идёт от администратора и первым делом останавливает службу. В
обоих режимах служба удаляется, а изменённые ею сетевые настройки (фильтры
пакетов, маршруты, DNS) возвращаются, так что у компьютера остаётся та сеть,
что была до установки.

| Режим | Удаляется | Остаётся |
|---|---|---|
| Удалить программу (по умолчанию) | Программа и её служба | Настройки, правила, данные службы и журнал аудита всех пользователей: после повторной установки всё продолжит работать как раньше |
| Удалить полностью | Ещё и данные службы и настройки того, кто удаляет программу | Журнал аудита, файлы правил, сохранённые вами в своих папках, и данные других учётных записей Windows |
| Удалить полностью вместе с журналом аудита | Ещё и журнал аудита | Файлы правил, сохранённые вами в своих папках, и данные других учётных записей Windows |

Данные, которые хранят другие учётные записи Windows на этом компьютере,
перечисляются, но не удаляются: программа удаления сообщает об этом и называет
папки, а каждый пользователь может удалить свои, войдя в свою учётную запись.

**EXE.** При удалении через «Параметры» > «Приложения» установщик спрашивает,
какой режим выбрать, а при полном удалении — стирать ли журнал аудита. Тихое
удаление данные сохраняет, если не попросить иначе:

```powershell
& "C:\Program Files\NetRuleRouter\unins000.exe" /VERYSILENT                                # данные остаются
& "C:\Program Files\NetRuleRouter\unins000.exe" /VERYSILENT /REMOVEALLDATA                 # удалить полностью
& "C:\Program Files\NetRuleRouter\unins000.exe" /VERYSILENT /REMOVEALLDATA /REMOVEAUDIT    # и журнал аудита
```

**MSI.** Удаление через «Параметры» > «Приложения» открывает окно
установщика: выберите «Удалить», и он спросит, какой режим выбрать, а при
полном удалении — стирать ли журнал аудита. Тихое удаление из консоли
администратора данные сохраняет, если не попросить иначе:

```powershell
msiexec /x NetRuleRouter-windows-<arch>-<версия>.msi /qn                                  # данные остаются
msiexec /x NetRuleRouter-windows-<arch>-<версия>.msi /qn REMOVEALLDATA=1                  # удалить полностью
msiexec /x NetRuleRouter-windows-<arch>-<версия>.msi /qn REMOVEALLDATA=1 REMOVEAUDIT=1    # и журнал аудита
```

`REMOVEAUDIT=1` действует только вместе с `REMOVEALLDATA=1`. Папки, оставшиеся
у других учётных записей Windows, MSI называет в своём журнале; чтобы его
сохранить, добавьте `/l*v <файл>`.

### Что нужно на машине сборки для установщиков

- **EXE:** [Inno Setup](https://jrsoftware.org/isinfo.php) 6.3 или новее в
  пределах версии 6, `ISCC.exe` в `PATH` или в папке установки по умолчанию.
- **MSI:** [WiX Toolset](https://wixtoolset.org/) 5.0.2 как инструмент .NET и
  два его расширения:

  ```powershell
  dotnet tool install --global wix --version 5.0.2
  wix extension add -g WixToolset.Util.wixext/5.0.2
  wix extension add -g WixToolset.UI.wixext/5.0.2
  ```

  Другие версии WiX отвергаются: WiX 6 и новее поставляются с лицензией,
  требующей платы за сопровождение.

Скрипт проверяет эти инструменты до сборки, поэтому без нужного запуск сразу
останавливается и называет команду, которая это исправит.

### Журналы установщиков

Оба установщика ведут журнал каждого запуска — и установки, и удаления — в
папке `%TEMP%` той учётной записи, от которой их запустили: EXE — текстовые
журналы с датой в имени и `NetRuleRouter-setup.log` для шагов со службой, MSI —
файлы `MSI….LOG`. Если установка или удаление пошли не так, приложите самые
свежие из них.

Во время работы оба мастера показывают, какой шаг идёт: закрытие программы,
остановка, регистрация и запуск службы. На последней странице EXE предлагает
кнопку **Показать журнал установки**, а MSI называет файл своего журнала.

Удаление из «Параметры > Приложения» тоже пишет журнал `Uninstall Log ….txt`
с датой в имени. Если же запустить `unins000.exe` напрямую, собственного
журнала Inno Setup не будет; шаги удаления, от сделанного выбора до конца,
записаны в `NetRuleRouter-setup.log`. Чтобы получить оба журнала, добавьте к
команде `/LOG`.

## Установка службы из переносимой папки

Установщики делают этот шаг сами. Из переносимой папки служба ставится из самой
программы («Настройки», «Управление службой») или командой `nrr-cli install`; в
обоих случаях система запросит подтверждение администратора.

Переносимая папка может оставаться там, куда вы её распаковали, — на рабочем
столе, на флэшке. Служба работает с системными правами, поэтому её никогда не
запускают из папки, которую может изменить обычный пользователь: установка из
такой папки копирует службу в `C:\Program Files\NetRuleRouter Service`, где
что-то менять могут только администраторы, и запускает её оттуда. Повторная
установка из более новой переносимой копии обновляет эту копию; удаление службы
убирает папку, удаление установщиком — тоже. Если потом переместить или удалить
переносимую папку, установленная служба продолжит работать. См.
[Security](../../SECURITY.md), раздел «Installation scope».

## Урезанный рантайм Qt

По умолчанию скрипт не кладёт то, что программа никогда не загружает:
собственные переводы Qt, программный растеризатор OpenGL, старый компилятор
шейдеров Direct3D, отладочные модули QML и все наборы стилей Qt Quick Controls,
кроме выбранного программой (плюс `Basic` — запасной вариант самого Qt). Это
около 37 МБ из 134 МБ полной выкладки.

Ключ `-Full` нужен, когда подозрение падает на Qt и требуется нетронутый
рантайм для сравнения.

## Если окно не запускается

Когда части установки не хватает, например удалена библиотека Qt или копия
не доделана, `NetRuleRouter.exe` и `NetRuleRouterTray.exe` показывают своё
сообщение вместо системной ошибки: установка неполная, переустановите
программу. В сообщении назван журнал с подробностями —
`%TEMP%\NetRuleRouter\launcher-main.log` (у трея — `launcher-tray.log`).

## Что нужно на машине сборки

- Rust и `cargo` в `PATH`
- Qt 6 с настольным набором целевого процессора: `msvc2022_64` для x64,
  `msvc2022_arm64` для ARM64 (с `-Headless` не нужен)
- Для пакета x64 — машина x64 с Windows; для пакета ARM64 — машина ARM64 или
  x64. При любом другом сочетании упаковка остановится с пояснением, а не
  смешает несовместимые компоненты
- Visual Studio с компонентом C++ — его библиотеки копируются в пакет. Пакету
  ARM64 нужны ещё средства сборки ARM64 из того же компонента
- `git` для штампа ревизии. Без него пакет всё равно соберётся, а ревизия
  запишется как `unknown`.

## Пакеты ARM64

`-Arch arm64` собирает пакет для Windows на ARM: та же папка, те же
установщики, с окном и треем, а с `-Headless` — без них.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\package-windows.ps1 -Arch arm64 -Zip -Installers
```

Что нужно машине сборки сверх списка выше:

- Цель Rust: `rustup target add aarch64-pc-windows-msvc`.
- `clang.exe` из LLVM или из компонента Visual Studio «Средства Clang C++ для
  Windows». Если его нет в `PATH`, скрипт сам ищет его в этих двух местах.
- Набор Qt `msvc2022_arm64`, на который указывает `CMAKE_PREFIX_PATH`, а если
  переменная не задана — самый новый в `C:\Qt`. `CMAKE_PREFIX_PATH`,
  указывающий на другой набор, отвергается до начала сборки.

На машине ARM64 этого достаточно. На машине x64 набор ARM64 — кросс-набор: своих
инструментов у него нет, поэтому `QT_HOST_PATH` должен указывать ещё и на набор
x64 той же версии Qt:

```powershell
$env:CMAKE_PREFIX_PATH = 'C:\Qt\6.8.3\msvc2022_arm64'
$env:QT_HOST_PATH = 'C:\Qt\6.8.3\msvc2022_64'
powershell -ExecutionPolicy Bypass -File .\scripts\package-windows.ps1 -Arch arm64 -Zip -Installers
```

Пакет ARM64, собранный на x64, проверяют на машине ARM64: на машине сборки он
не запустится.

## Ограничения

- **Только Windows.** Linux-аналог — отдельная работа (юнит systemd, нет
  `windeployqt`, нет wintun), поэтому он появится вместе со сборкой под Linux,
  а не переводом этого скрипта.
- **Бинарники и установщики не подписаны**, поэтому SmartScreen предупредит
  при первом запуске.
- **На одной машине — один установщик.** EXE и MSI — две отдельные установки
  одной программы: чтобы перейти с одного на другой, сначала удалите первую.
- **У файла `.msi` в проводнике — значок установщика Windows:** его рисует
  сама Windows для любого MSI, что бы ни было внутри пакета. После установки
  в «Параметры» > «Приложения» виден значок NetRuleRouter.
- **В `scripts\` лежит только то, что нужно пользователю пакета:**
  `reset-network.ps1`, `service-status.ps1`, `uninstall-service.ps1` и
  `purge-data.ps1`; в установленной копии есть ещё `setup-actions.ps1`,
  который запускают установщики. Сценарии сборки, проверки и разработки
  остаются в рабочей копии. Для повседневных проверок и восстановления сети есть консоль
  рядом с программой: `nrr-cli status`, `nrr-cli diag doctor`,
  `nrr-cli reset-network --confirm`. См. [консоль](cli.md).
