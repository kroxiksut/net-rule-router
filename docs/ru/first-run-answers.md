# Ответы на вопросы настройки, заданные заранее

При первом запуске NetRuleRouter задаёт несколько вопросов: какие подключения
использовать, включать ли защиты и с какого набора правил начать. Если ответы
уже известны — их собрал установщик или портативная копия готовится сразу для
нескольких машин — их можно передать файлом, и окно настройки не появится.

## Куда положить файл

Назовите его `first-run.json` и поместите в одно из двух мест:

- рядом с `NetRuleRouter.exe` (портативная копия или папка программы у
  установщика);
- в папку данных компьютера, `%ProgramData%\NetRuleRouter\`.

Если файл есть в обоих местах, побеждает тот, что лежит рядом с программой.

## Что в нём

```json
{
  "primary-connection": "Ethernet",
  "secondary-connection": "hidemy.name VPN",
  "kill-switch": true,
  "doh-lockdown": true,
  "fake-ip": true,
  "rule-set": "ru/osnovnoy-i-zarubezh",
  "language": "ru"
}
```

| Ключ | Что означает |
|---|---|
| `primary-connection` | Имя подключения, по которому идёт всё по умолчанию. Сопоставляется с именем подключения из Windows или с описанием адаптера. |
| `secondary-connection` | Имя дополнительного подключения, куда правила направляют трафик. |
| `kill-switch` | `true` — придержать трафик, а не выпускать его по основному подключению, пока дополнительное не поднято. |
| `doh-lockdown` | `true` — не давать браузерам разрешать имена маршрутизируемых сайтов в обход NetRuleRouter. |
| `fake-ip` | `true` — направлять сайты по имени, чтобы адрес, общий с другим сайтом, не утягивал его за собой. |
| `rule-set` | Встроенный набор правил, с которого начать, в виде `<страна>/<набор>`. `"none"` — начать с пустой таблицы. |
| `language` | Язык интерфейса (`"ru"`, `"en"`). Не указывайте, чтобы взять язык системы. |

Все ключи необязательны. Незнакомый ключ приводит к отказу от файла целиком —
он не применяется наполовину, поэтому опечатка не оставит защиту выключенной
незаметно.

## Когда окно настройки всё равно появится

Окно пропускается, только если заданы `kill-switch`, `doh-lockdown`, `fake-ip`
и `rule-set`. Имена подключений в этот перечень не входят: адаптер ВПН обычно
не существует, пока клиент не подключится в первый раз, и установщик не может
назвать его заранее. Если указанное подключение на машине не найдено, роль
остаётся незаполненной, и приложение спросит о ней обычным образом.

Файл только читается. Изменение настроек в приложении его не трогает, и после
первого запуска приложение к нему не обращается.
