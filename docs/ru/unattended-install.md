# Установка без вопросов

[English](../en/unattended-install.md) · **Русский**

Ставьте NetRuleRouter сценарием, вместе с другими программами, и сразу со
своими правилами для каждого пользователя компьютера. Во время установки
ничего не спрашивается, а файл правил, который нельзя использовать, проваливает
установку, а не оставляет компьютер настроенным наполовину.

## Windows

Через MSI:

```
msiexec /i NetRuleRouter.msi /qn /l*v C:\temp\nrr-setup.log ^
  PROVISION=C:\deploy\rules_primary.txt ^
  PROVISION_SECONDARY=C:\deploy\rules_secondary.txt ^
  PROVISION_SETTINGS=C:\deploy\settings.yaml ^
  SECONDARY_UNSET=direct
```

Установщик EXE принимает те же имена как ключи:

```
NetRuleRouter-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /LOG=C:\temp\nrr-setup.log ^
  /PROVISION=C:\deploy\rules_primary.txt /SECONDARY_UNSET=direct
```

| Параметр | Что даёт |
|---|---|
| `PROVISION` | Правила основного подключения |
| `PROVISION_SECONDARY` | Правила дополнительного подключения |
| `PROVISION_SETTINGS` | Файл настроек, выгруженный на другом компьютере: его правила устанавливаются так же, как из файлов правил, его маршрут по умолчанию (основное или дополнительное подключение) становится начальным, а защита от утечки — самой слабой, с которой начинает пользователь. Подключения из него не переносятся — у каждого компьютера они свои. Правила одного маршрута задавайте один раз: файл правил и правила в файле настроек для одного маршрута прерывают установку с кодом 12 |
| `SECONDARY_UNSET` | `direct` (по умолчанию): пока дополнительное подключение не выбрано, его правила идут напрямую. `block`: до выбора они удерживаются, а пользователь, ещё не выбравший защиту от утечки, начинает с варианта **«Только сайты из правил»** |

Пути указывайте полные. Любой параметр можно не задавать.

Тихая установка не показывает страницу с соглашением, поэтому каждую учётную
запись Windows, в том числе ту, от имени которой шла установка, программа
попросит принять пользовательское соглашение при первом запуске. После
установки через мастер учётную запись, которая приняла соглашение в нём,
программа больше не спрашивает; все остальные учётные записи спросит.

### Папка, компоненты и ярлыки

У каждого выбора из мастера установки есть форма для командной строки. Без
неё новая установка берёт значение по умолчанию, а обновление сохраняет
прежний выбор.

| Выбор | MSI | EXE | По умолчанию |
|---|---|---|---|
| Папка установки внутри Program Files | `INSTALLFOLDER=<папка>` | `/DIR=<папка>` | `C:\Program Files\NetRuleRouter` |
| Не ставить терминальный интерфейс (`nrr-tui`) | `NRR_TUI=0` | `/COMPONENTS=main,docs` | Ставится |
| Не ставить офлайн-документацию | `NRR_DOCS=0` | `/COMPONENTS=main,tui` | Ставится |
| Ярлык на рабочем столе | `NRR_DESKTOP_SHORTCUT=1` | `/MERGETASKS=desktopicon` | Нет |
| `nrr-cli` и `nrr-tui` в PATH | `NRR_ADD_TO_PATH=1` | `/MERGETASKS=addtopath` | Не добавляются |

Окно, значок в трее, фоновая служба и консоль (`nrr-cli`) ставятся всегда.
Папка вне Program Files прерывает установку до того, как что-либо
установлено: MSI возвращает 1603, установщик EXE — 7. Чтобы при обновлении
отменить прежний выбор, укажите его заново: `NRR_TUI=1` или `NRR_DOCS=1`, а
для установщика EXE — полный список, например `/COMPONENTS=main,tui,docs` или
`/TASKS=addtopath` (пустой `/TASKS=""` снимает все задачи). `/COMPONENTS=main`
не ставит ни терминальный интерфейс, ни документацию. Несколько задач
перечисляются через запятую: `/MERGETASKS=desktopicon,addtopath`.

Без офлайн-документации пункт «Справка > Документация» в программе открывает
эти страницы в интернете.

### В чьём меню «Пуск» появится ярлык

Программа устанавливается один раз на весь компьютер, и маршрутизация работает
для всех учётных записей Windows при любом выборе. `NRR_INSTALL_FOR` (MSI) и
`/INSTALL_FOR` (установщик EXE) определяют только, у кого NetRuleRouter
появится в меню «Пуск» и на рабочем столе и в чей PATH попадут консольные
инструменты:

| Значение | Ярлык и PATH |
|---|---|
| `all` | У каждого пользователя компьютера. Так по умолчанию при новой установке |
| `me` | Только у учётной записи, от имени которой работает установщик: для MSI — у той, что запустила `msiexec` |

Без этого параметра обновление сохраняет выбор, сделанный при прежней
установке, а обновление с другим выбором переносит ярлыки и запись в PATH.
Любое другое значение останавливает установку до того, как что-либо
установлено: MSI возвращает 1603, установщик EXE — код 1. В пакете без окна
ярлыков нет, а консольные инструменты всегда попадают в PATH всех
пользователей.

## Linux

Перед установкой `.deb` или `.rpm` положите файлы в
`/etc/netrulerouter/provision/` (владелец — root): `rules_primary.txt`,
`rules_secondary.txt`, `settings.yaml` и `options.conf` со строкой
`secondary-unset = direct` или `secondary-unset = block`. Служба заберёт их при
первом запуске.

Из архива — передайте файлы установщику:

```
sudo ./install.sh --provision rules_primary.txt --provision-secondary rules_secondary.txt \
  --provision-settings settings.yaml --secondary-unset block
```

## Что происходит после установки

- Правила становятся общими правилами, с которых начинает каждый пользователь
  компьютера. Пользователь, который потом правит свои правила, сохраняет свои
  правки; общие правила остаются теми, что вы поставили.
- Пока пользователь не подтвердит основное подключение, сеть работает так, как
  будто программы нет. Трей предлагает подключение компьютера к интернету —
  подтвердить одним нажатием или выбрать другое.
- Файлы применяются один раз. После этого они остаются, переименованные, в
  папке подготовки службы (`%ProgramData%\NetRuleRouter\provision` на Windows,
  `/etc/netrulerouter/provision` на Linux) — видно, что они взяты.

## Когда файл нельзя использовать

Файлы проверяются до того, как что-то будет установлено. Файл, который нельзя
использовать, проваливает установку, а причина — в журнале установки:

| Код | Что не так |
|---|---|
| 10 | Правила основного подключения |
| 11 | Правила дополнительного подключения |
| 12 | Файл настроек |
| 13 | Значение `SECONDARY_UNSET` |
| 14 | Файлы не удалось подготовить для службы |

MSI при этом возвращает 1603, установщик EXE — 7, а `install.sh` — код из
таблицы. Проверить файлы заранее можно командой
`nrr-service provision-check --primary <файл>` на Windows или
`nrr-serviced provision-check --primary <файл>` на Linux: она ничего не меняет и
возвращает те же коды.

Если программа установлена, но её фоновую службу не удалось зарегистрировать или
запустить, установщик EXE возвращает 15, а MSI отменяет установку и возвращает
1603.
