# Посайтовая маршрутизация через виртуальные адреса (fake-IP)

[English](../en/fake-ip.md)

NetRuleRouter маршрутизирует трафик посайтово. Но многие сайты живут за общей
инфраструктурой — сеть доставки контента (CDN) может отвечать за десятки не
связанных между собой сайтов с одного IP-адреса. Когда два сайта делят один
адрес, решение, принятое по адресу, не может их различить: маршрутизация или
защита одного затронет другой. Функция fake-IP убирает эту неоднозначность.

## Что она даёт

Когда fake-IP включён, каждый маршрутизируемый сайт получает **собственный**
частный адрес вместо реального. Поскольку у каждого сайта теперь свой адрес,
маршрутизация и защита от утечек снова становятся по-настоящему посайтовыми —
даже для сайтов, делящих один реальный адрес сервера. Два следствия, на которые
можно опереться:

- **Нет коллатерали.** Маршрутизация или защита одного сайта больше не может
  задеть другой сайт только потому, что тот делит с ним реальный адрес.
- **Нет гонки на первом соединении.** Решение о маршруте сайта готово ещё до
  того, как самое первое соединение к нему покинет ваш компьютер, поэтому первый
  запрос никогда не уходит не туда, пока защита «догоняет».

Функция работает без анализа и без расшифровки вашего трафика. Она никогда не
выступает «человеком посередине»: зашифрованные соединения остаются
зашифрованными от края до края, и никакие сертификаты не устанавливаются.

## Что для неё нужно

Fake-IP строится поверх **локального DNS-резолвера (Режим B)** — именно резолвер
выдаёт каждому сайту его частный адрес — поэтому функция доступна только при
выбранном Режиме B. В реактивном режиме по умолчанию флажок неактивен.

Для доставки трафика, адресованного этим частным адресам, нужен виртуальный
сетевой адаптер:

- **Windows** поставляется с адаптером **Wintun** (издатель — WireGuard LLC, тот
  же адаптер использует WireGuard и ряд известных коммерческих VPN-клиентов).
  Включение fake-IP загружает этот драйвер; при выключении адаптер не создаётся.
  Файл поставляется ровно в том виде, в каком его подписал автор, и используется
  только через его опубликованный интерфейс. См.
  [Сторонние компоненты](third-party-components.md).
- **Linux и macOS** предоставляют равнозначный адаптер в самой операционной
  системе, поэтому сборки для этих систем не везут никакого дополнительного
  драйвера.

Экран настроек показывает статус драйвера рядом с флажком, так что перед тем как
полагаться на функцию, можно убедиться, что подлинный драйвер на месте.

## Когда она не применяется

Fake-IP сознательно используется не для каждого соединения:

- **Одноранговые (P2P) и криптовалютные приложения** сохраняют реальные адреса:
  по умолчанию они идут по основному каналу. Маршрут им можно назначить самому
  в разделе **«Интерфейсы и маршруты» → «Настроить маршруты»**, как и любой
  другой группе приложений.
- **Адреса, введённые напрямую, а также локальные и интранет-имена** — «голый»
  IP-адрес, `localhost`, однословные имена машин, `.local` и подобные — всегда
  используют реальный адрес, поскольку у них нет публичного назначения для
  маршрутизации.

В каждом из этих случаев соединение просто использует реальный адрес, а
остальная защита NetRuleRouter продолжает действовать.

## Известное ограничение: DNS-over-HTTPS

Fake-IP работает, управляя ответом, который даёт системный DNS-резолвер.
Приложение, которое резолвит имена самостоятельно через DNS-over-HTTPS (DoH) или
DNS-over-TLS, обходит системный резолвер и потому никогда не получает частный
адрес, а подключается напрямую к реальному. Обычный случай — браузеры.

Два способа закрыть эту брешь:

- Отключить DoH в браузере или приложении, чтобы оно снова использовало
  системный резолвер.
- Включить в настройках **Блокировать браузерный DoH/DoT** — тогда разрешение
  имён откатится к открытому DNS, который резолвер способен обслужить.

## Как включить

Fake-IP **по умолчанию выключен**. Чтобы включить: Настройки → Маршрутизация →
включите локальный DNS-резолвер (Режим B), затем отметьте **Разводить сайты по
виртуальным адресам (fake-IP)**. Изменение применяется сразу; перезапуск фоновой
службы не нужен.
