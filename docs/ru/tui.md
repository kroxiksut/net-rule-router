# Терминальный интерфейс `nrr-tui`

**Русский** · [English](../en/tui.md)

`nrr-tui` — это NetRuleRouter в терминале. Он делает то же, что окно
программы, — состояние, первоначальная настройка, адаптеры и маршруты,
правила, предложения, диагностика, настройки — на машине, куда вы заходите по
SSH, на сервере без рабочего стола или просто для тех, кому удобнее работать с
клавиатуры. Не переносятся только настройки самого окна: тема, шрифты и
подобное.

Это тот же продукт, а не второй: он работает с той же фоновой службой, правит
те же правила, а экраны повторяют разделы программы, поэтому совет, написанный
для одного интерфейса, работает и в другом.

> Предварительная версия. Экраны появляются по очереди; ещё не готовый экран
> так и говорит, а не делает вид.

## Только в терминале

`nrr-tui` работает только в живом терминале. Запущенный из сценария, через
конвейер или с перенаправленным выводом, он не стартует: сообщает об этом и
завершается с кодом `3`. Для чтения и диагностики из сценариев есть
[консоль `nrr-cli`](cli.md) — это её работа, и на её коды возврата сценарий
может опираться.

## Запуск

В Windows `nrr-tui.exe` лежит рядом с `NetRuleRouter.exe`. В PowerShell,
находясь в этой папке, добавьте перед именем `.\`, как и для консоли:

```powershell
.\nrr-tui.exe
```

В Linux установка службы делает `nrr-tui` доступным по имени:

```bash
nrr-tui
```

Ключи:

| Ключ | Что делает |
|------|------------|
| `--plain` | Построчный режим для экранного чтеца: ничего не перерисовывается, каждое изменение печатается новой строкой, меню нумерованы |
| `--no-color` | Без цвета. То же даёт переменная окружения `NO_COLOR` с любым значением |
| `--ascii` | Простые символы вместо линий рамок — для терминалов и шрифтов, которые плохо рисуют псевдографику |
| `--lang <язык>` | Язык интерфейса, например `en` или `ru`. Без ключа берётся язык системы, а если для него нет перевода — английский |
| `--wizard` | Открыть первоначальную настройку, чтобы пройти её заново |
| `--bell` | Звуковой сигнал терминала при новом уведомлении. По умолчанию выключен |
| `--help`, `--version` | Напечатать список ключей или версию |

Переменная `NRR_TUI_PLAIN=1` включает построчный режим без `--plain` при
каждом запуске — её удобно задать в профиле оболочки. Построчный режим, режим
без цветов и простые символы можно включить и в «Настройки», «Терминал»; они
запоминаются для вашей учётной записи и действуют со следующего запуска.

При первом запуске, если вы ещё ничего не настраивали, первоначальная
настройка открывается сама.

## Экраны

| Клавиша | Экран | Что там делается |
|---------|-------|------------------|
| `1` | Статус | Работает ли служба и активна ли маршрутизация, ограничена или на паузе — словами; оба маршрута и их адаптеры; лента уведомлений, где у каждого уведомления свои действия (см. ниже) |
| `2` | Первый запуск | Язык, какой адаптер основной, а какой дополнительный, набор правил для начала, защита от утечки, маршрутизация сайтов по имени, подробные журналы диагностики |
| `3` | Интерфейсы и маршруты | Адаптеры с типом, состоянием и адресами; какой из них несёт какой маршрут; проверка адаптера |
| `4` | Правила | Таблица правил с поиском и фильтром; добавить, изменить, удалить, включить и выключить; пометить правило «Не уверен — проверить, где работает», чтобы оно шло по своему маршруту, пока сайт там открывается, а когда сайт открывается только через другой, шло через него, и приложение предлагало перенести правило; ваша папка наборов правил; импорт и экспорт; применение изменений. `c` проверяет, доходит ли основной маршрут до сайтов из правил дополнительного маршрута, и ответ виден рядом с каждым правилом — так понятно, какие правила ещё действительно нужны; `Shift+O` ставит первыми сайты, до которых основной маршрут не доходит. `v` добавляет правило для шлюза VPN, чтобы VPN, которому разрешено подключаться только из одной сети (например, рабочий VPN, доступный только из-за рубежа), всегда подключался через выбранный маршрут: спрашивает программу и маршрут, показывает адреса, к которым программа недавно подключалась, и принимает номер или введённый адрес |
| `5` | Перекрытия | Пары правил, которые касаются одного и того же трафика, и какой маршрут на деле побеждает |
| `6` | Предложенные адреса | Принять или отклонить то, что программа предлагает добавить в правила |
| `7` | Трассировка соединений | Последние соединения и по какому маршруту они ушли, с объяснением для любой строки. `o` открывает список того, что было заблокировано, пока дополнительный маршрут лежал. `h` переключает на вашу историю соединений — строка на программу и адресат и сколько раз она соединялась, — а `t` выбирает период: последний час, сегодня или последние 7 дней. `g` группирует список по программе или по папке, где программа лежит, и запоминает выбор; в группе папки `f` открывает правило сразу на всю папку. `i` и `a` открывают правило для адреса или программы выбранного соединения |
| `8` | Кэш | Имена и адреса, в которые они разрешились; поиск и очистка |
| `9` | Диагностика и логи | Состояние службы, тревоги безопасности, объяснение для хоста, журнал, выгрузка диагностического архива. `c` проверяет сайт, который не открывается (см. ниже) |
| `0` | Настройки | Уведомления и скрытые вами уведомления, поведение маршрутизации (в том числе отключение правил на время), что делать при сбое применения, управление службой, пресеты, журналы, хранение и история соединений, статистика трафика, обновления и собственные параметры терминального интерфейса. В меню «Настройки» раскрываются разделами, и стрелки сразу ведут к нужному |

Изменения правил применяются так же, как в программе: сначала вы видите
сводку — что добавится, что удалится, что изменится, — затем подтверждаете.

### Ещё на экране «Правила»

- **Запрет.** В форме правила маршрутом можно выбрать и *Запретить*:
  назначение не пускают ни через одно подключение, а в файле правил оно
  записано как `!значение`. `f` может показать только запреты.
- **Программы по папке.** Правило приложения может назвать файл программы или
  папку (`C:\Apps\Tool\*`, `/opt/tool/*`). `Ctrl+F` в форме переключает
  правило папки между «с подпапками» и «только эта папка»; правило, которое
  отвергает защита системных программ, отвергается до сохранения, с причиной.
- **Несколько правил сразу.** `Shift+A` или `F2` в форме добавления принимает
  строки файла правил, набранные или вставленные (строки с `!`, `?`, `#` и
  `--- Раздел` работают как в файле). Каждая строка проверяется до того, как
  что-то добавится; невзятые строки остаются в форме. Всё добавленное
  попадает в список одним шагом, и одно применение отправляет его вместе.
- **Недавние изменения.** `Shift+R` показывает правила, которые вы добавили
  или изменили за последний час, сегодня или за последние 7 дней, новые
  сверху, и удалённые; `Shift+U` возвращает удалённое правило с прежним
  маршрутом и включением.
- **Значение не в своём разделе.** `Shift+T` даёт выбранному правилу тот тип,
  которым является его значение (например, имя программы, записанное как
  домен); `Shift+M` делает это для всех таких правил. В форме то же делает
  `Ctrl+T`.
- **Разрешено вопреки защите.** `Shift+P` на правиле с пометкой `+override`
  подтверждает его вопреки защите системных программ на выбранный срок или
  снимает подтверждение. Подтверждению, которое задевает не только ваши
  программы, нужны права администратора: на Windows подтвердите его в окне
  программы или из терминала, запущенного от имени администратора; на Linux
  терминал спросит пароль администратора.
- **Группы и файлы.** `g` отправляет группу программ или машины гипервизора
  по маршруту; там `m` показывает машины гипервизора и что нужно каждому
  сетевому адаптеру, чтобы правила сайтов работали внутри машины, а для
  NAT-адаптера VirtualBox `a` отправляет весь трафик машины по
  дополнительному маршруту, `f` снова отдаёт его вашим правилам. `F`
  сравнивает привязанные файлы правил с действующими правилами и сводит их.
- **Списки целиком.** `X` сохраняет правила одного маршрута в файл, `L`
  добавляет демонстрационные правила, `W` после вопроса очищает все правила,
  `Z` возвращает базовые правила. `*` отмечает правила, а `B` действует сразу
  на все отмеченные.

### Проверка сайта, который не открывается

`c` на экране «Диагностика» спрашивает имя сайта и говорит, виновата сеть или
сам сайт: для сайта, его имён входа и имён, замеченных вместе с ним, — по
какому маршруту идёт каждое и отвечает ли оно там. Вывод подсказывает, что
делать дальше: сайт отвечает и браузеру нужно очистить файлы cookie, вход
идёт не тем маршрутом, что сайт, сам маршрут не работает или сайт запрещён
вашим же правилом. Та же проверка — `c` на строке трассировки соединений и на
уведомлении о сайте в ленте и `k` на предложенном адресе. Без вашей просьбы
ничего не проверяется.

### Уведомления

Лента на экране «Статус» хранит каждое уведомление, пока вы его не уберёте.
Среди них: открытый вами сайт не открывается через основное подключение,
основное или дополнительное подключение то и дело обрывается, служба
остановилась сама (с командами, которые снова её запускают или возвращают
сеть), соединения, задержанные, пока дополнительный маршрут лежал. На
уведомлении `m` перестаёт показывать похожие — этот вид уведомлений на день,
7 дней, 30 дней или навсегда, а для заблокированного соединения — этот сайт,
эту программу или все уведомления о блокировках, — а `s` откладывает
уведомление о заблокированном соединении. Скрытое перечислено, и его можно
снова показать, в «Настройки», «Уведомления»; оно скрыто и в окне, и в трее.

### Отключить правила на время

«Настройки», «Поведение маршрутизации», *Применение правил* отключает вашу
маршрутизацию и защиту от утечки на 15 минут, на час, на 4 часа, до
перезапуска компьютера или службы или пока вы не включите их снова. Когда
время выходит, они включаются сами, пауза на время переживает перезапуск
службы, а у остальных вошедших правила продолжают действовать.

## Клавиши

Всё делается с клавиатуры; мышь не нужна никогда. Одна и та же клавиша значит
одно и то же на любом экране.

| Клавиша | Действие |
|---------|----------|
| `F1` или `?` | Справка по текущему экрану — доступна всегда |
| `1`–`9`, `0` | Перейти к экрану |
| `Tab`, `Shift+Tab` | Переход между панелями экрана |
| Стрелки, `Enter` | Перемещение по списку, открыть или подтвердить |
| `Пробел` | Включить или выключить выбранное правило или настройку; в форме правила — сменить тип или маршрут |
| `/` | Поиск в списке |
| `Esc` | Назад или отмена |
| `Ctrl+S` | Применить изменения правил |
| `q` | Выход. Если есть неприменённые изменения, спросит: применить, отбросить или остаться |

В построчном режиме (`--plain`) те же действия предлагаются нумерованными
пунктами: наберите номер и нажмите `Enter`; `h` или `?` печатает справку, `q` —
выход.

## Доступность

- **Экранные чтецы.** `--plain` — режим для NVDA и Экранного диктора в консоли
  Windows, для Orca, Speakup и BRLTTY в Linux. Ничего не прыгает по экрану;
  каждое изменение приходит новой строкой, которую можно прочитать.
- **Смысл никогда не передаётся только цветом.** У каждого состояния есть
  слово — «активна», «ограничена», «ошибка», — а цвет его лишь повторяет;
  основное и дополнительное подключение различаются по имени, цвет лишь помогает
  глазу. Используются только именованные цвета самого терминала, поэтому экран
  следует его теме, светлой или тёмной. С `--no-color` или `NO_COLOR` ничего не
  теряется.
- **Фокус виден без цвета:** выбранная строка отмечена знаком `>` и выделена
  жирным.
- **Ни одна линия рамки не несёт смысла сама по себе.** У панелей текстовые
  заголовки, а `--ascii` заменяет рамки простыми символами.
- **Ничего на время.** Ни один вопрос не исчезает сам и не отвечает за вас, а
  каждое уведомление остаётся ещё и в ленте на экране «Статус».
- **Читается при 80×24.** В узком терминале текст переносится, а не
  обрезается; в широком используется всё место.
- **Каждая ошибка говорит словами, что случилось и что делать дальше**, а не
  кодом.

## Права

- **Свои правила не требуют прав администратора.** Правьте и применяйте их из
  обычного терминала; действуют они для вас.
- **Экран правил изменяет один набор за раз**, и заголовок говорит какой:
  ваши правила или базовый набор, по которому работают все пользователи без
  собственных правил. Клавиша `b` переключает их (в построчном режиме —
  команда `b`). Предложения, проверка основного маршрута и перенос `?`-правил
  меняют ваши собственные правила, поэтому работают, когда на экране ваши
  правила.
- **Общий базовый набор**, настройки всего компьютера и **управление
  службой** — установка, запуск, остановка — требуют прав администратора. В
  Windows запустите терминал от имени администратора и нажмите `b`, чтобы
  править общий базовый набор, или правьте его в окне приложения — оно само
  запросит права администратора. Из обычного терминала базовый набор можно
  посмотреть, но изменение в нём не применится: интерфейс предложит
  запустить `nrr-tui` заново из терминала, открытого от имени
  администратора. В Linux `nrr-tui` спросит пароль администратора прямо в
  терминале, и по SSH тоже; под `sudo` базовый набор открыт сразу. В
  построчном режиме (`--plain`) пароль не спрашивается: интерфейс показывает
  команду с `sudo`.
- Когда служба не установлена или не запущена, интерфейс говорит, что именно,
  показывает точную команду `nrr-cli`, которая это исправит, и продолжает
  проверять, пока служба не ответит. До тех пор он показывает только то, что
  уже знает, и не выдаёт это за свежие данные.

## Windows по SSH

В Windows правила действуют для пользователя, вошедшего в Windows — на
экране или по удалённому рабочему столу. Вошедший только по SSH может
смотреть и править свои правила в `nrr-tui`, и они сохраняются, но
действовать начинают, только пока тот же пользователь вошёл и в Windows.
В таком сеансе об этом говорит строка состояния. Режим, при котором вся
машина маршрутизируется по одному набору правил, запланирован в одном из
следующих выпусков.

## Серверы на Linux

В Linux правила действуют для пользователя, который вошёл в систему. Если вы
управляете своими правилами через `nrr-tui` по SSH, они действуют, пока у вас
есть сеанс на этой машине, — или постоянно, если для вашей учётной записи
включено сохранение сеанса:

```bash
sudo loginctl enable-linger "$USER"
```

Каждый вошедший — за экраном или по SSH — одновременно маршрутизируется своими
правилами; см. [Несколько пользователей на одном компьютере](several-users.md).
Фоновые службы следуют правилам того, кто вошёл первым. Режим, в котором вся машина, включая контейнеры, маршрутизируется по
одному набору правил, запланирован на один из следующих выпусков.
