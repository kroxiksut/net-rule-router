# Сборка пакетов для Linux

[English](../en/packaging-linux.md) · **Русский**

`scripts/package-linux.sh` превращает релизную сборку в пакеты, которые
ставятся на машину без Rust и без репозитория: `.deb` для Debian, Ubuntu и
Astra Linux, `.rpm` для семейства Red Hat (RHEL, AlmaLinux, Rocky, Fedora,
РЕД ОС) и архивы `.tar.gz` для всех остальных. Как собрать сами программы —
на странице [Сборка из исходников (Linux)](building-linux.md).

## Что получается

| Файл | Что в нём |
|---|---|
| `netrulerouter_<версия>_amd64.deb`, `netrulerouter-<версия>.x86_64.rpm` | Служба, консоль `nrr-cli` и [терминальный интерфейс `nrr-tui`](tui.md) |
| `netrulerouter-gui_<версия>_amd64.deb`, `netrulerouter-gui-<версия>.x86_64.rpm` | Окно и значок в трее, с пунктом меню; требует `netrulerouter` той же версии |
| `netrulerouter-<версия>-linux-x86_64.tar.gz` | Всё сразу — для систем, которые не принимают ни тот, ни другой формат пакетов |
| `netrulerouter-headless-<версия>-linux-x86_64.tar.gz` | То же без окна и трея |
| `SHA256SUMS` | Контрольные суммы всего перечисленного |

Выше — имена сборки x86_64. У пакетов для 64-битного ARM на их месте стоит
`arm64` (`.deb`) или `aarch64` (`.rpm`, архивы): скрипт называет пакеты по
машине, на которой запущен, или по `--arch`.

**Полная** установка — это `netrulerouter` плюс `netrulerouter-gui`, установка
**без GUI** — один `netrulerouter`. Добавить или убрать окно позже — значит
поставить или удалить один пакет; служба и её данные при этом не затрагиваются.

## Как собрать пакеты

Скрипту нужно несколько инструментов из репозиториев самого дистрибутива:

| Инструмент | Debian, Ubuntu, Astra | Семейство RHEL, РЕД ОС |
|---|---|---|
| `dpkg-deb`, `dpkg-shlibdeps` (для `.deb`) | `sudo apt install dpkg-dev` | `.deb` собирается на системе семейства Debian |
| `rpmbuild` (для `.rpm`) | `sudo apt install rpm` | `sudo dnf install rpm-build` |
| `readelf` | `sudo apt install binutils` | `sudo dnf install binutils` |

Если инструмента нет, ошибка называет его и пакет, в котором он лежит.
`--formats` позволяет пропустить формат, который собрать нельзя или не нужно.

Полный набор — на системе с Qt 6.6 или новее (Ubuntu 24.10 и новее, Debian 13,
Астра 1.8, Fedora):

```bash
./scripts/package-linux.sh --build
```

Без GUI, где Qt не нужен вовсе, — так собирают на Astra Linux 1.7, РЕД ОС 7.3
или родственниках RHEL 8:

```bash
./scripts/package-linux.sh --headless --build
```

Без `--build` скрипт упаковывает релизные бинарники, которые уже лежат в
каталоге сборки Cargo. Пакеты складываются в `target/packages/`.

| Параметр | Что делает |
|---|---|
| `--build` | Сначала собрать релизные бинарники. |
| `--headless` | Без GUI: ни `netrulerouter-gui`, ни полного архива. Qt не нужен. |
| `--formats deb,rpm,tar` | Собрать только перечисленные форматы. По умолчанию — все три. |
| `--arch x86_64` | Целевая архитектура, `x86_64` или `aarch64`. По умолчанию — архитектура этой машины. |
| `--release N` | Номер выпуска пакета — для пересборки той же версии. По умолчанию `1`. |
| `--out DIR` | Куда класть пакеты. По умолчанию `target/packages`. |
| `--maintainer "Имя <почта>"` | Сопровождающий в `.deb` и упаковщик в `.rpm`; по умолчанию `NetRuleRouter <fmalkov91@gmail.com>`. Читается и из `NRR_PACKAGE_MAINTAINER`. |

### На какой машине собирать

Программа под Linux работает на той библиотеке C (glibc), с которой собрана, и
на любой более новой, но не на более старой. Собирайте на самой старой системе,
на которую должны ставиться пакеты:

- пакеты без GUI, собранные на системе с glibc 2.28 (Astra Linux 1.7, РЕД ОС
  7.3, RHEL 8 и родственники), ставятся и на все более новые системы;
- GUI нужен Qt 6.6 или новее, поэтому он собирается на системе, где такой Qt
  есть, и ставится на системы не старее её.

Скрипт печатает самую старую glibc, которую принимают бинарники, записывает её
в `build-info.json` внутри пакета, и сам пакет её объявляет — более старая
система откажется ставить пакет, а не упадёт при запуске.

GUI нужно собирать с Qt из пакетов дистрибутива. Сборка с Qt, распакованным в
домашнюю папку, отклоняется: установленная программа искала бы библиотеки в
папках машины, на которой её собрали.

## Установка

```bash
# Debian, Ubuntu, Astra: полный вариант, или только первый файл — без GUI
sudo apt install ./netrulerouter_*.deb ./netrulerouter-gui_*.deb

# Семейство RHEL, РЕД ОС
sudo dnf install ./netrulerouter-*.rpm ./netrulerouter-gui-*.rpm
```

Служба запускается сразу, а потом при каждой загрузке. `nrr-cli`, `nrr-tui` и,
с GUI, `netrulerouter` доступны по имени из любой оболочки, а в меню приложений
появляется пункт NetRuleRouter.

Если Qt в системе старше 6.6, менеджер пакетов откажется ставить
`netrulerouter-gui` и назовёт недостающие пакеты Qt. Тогда либо поставьте Qt
поновее из своего дистрибутива (репозиторий backports или более новый выпуск),
либо пользуйтесь NetRuleRouter без окна: один `netrulerouter` даёт службу и
[терминальный интерфейс](tui.md), в котором есть всё то же, что в окне. Так же
система с nftables старше 0.9.6 откажется ставить пакет.

Из архива:

```bash
tar xzf netrulerouter-<версия>-linux-x86_64.tar.gz
cd netrulerouter-<версия>-linux-x86_64
sudo ./install.sh
```

Архив раскладывает файлы туда же, куда пакеты, но требования за вас никто не
проверит; они перечислены в его `README.txt`. Где дистрибутив принимает пакет,
лучше ставить пакет.

## Что нужно каждому варианту

| | Без GUI | Полный |
|---|---|---|
| systemd | обязательно | обязательно |
| nftables 0.9.6 или новее | обязательно | обязательно |
| iproute2 | обязательно | обязательно |
| glibc | не старее, чем на машине сборки | не старее, чем на машине сборки |
| polkit | желательно: без него привилегированные изменения доступны только root | обязательно |
| Qt 6.6 или новее (Qt Quick, Controls, Layouts, Dialogs, `Qt.labs.platform`) | не нужен | обязательно |

Имена зависимостей в `.deb` — как в Debian и Ubuntu, в `.rpm` — как в RHEL и
Fedora. Дистрибутивы, где пакеты называются иначе (Альт, openSUSE), могут не
разрешить зависимости `.rpm`; там используйте архив.

## Обновление

Поставьте новые пакеты поверх старых тем же способом. Работающая служба сразу
переходит на новую версию; остановленная или отключённая вами такой и
остаётся. Правила, настройки и история сохраняются.

## Удаление

| Что запускаете | Служба | Сеть | Данные службы | Журнал аудита |
|---|---|---|---|---|
| `sudo apt remove netrulerouter-gui netrulerouter` | остановлена и удалена | возвращена | остаются | остаётся |
| `sudo apt purge netrulerouter-gui netrulerouter` | остановлена и удалена | возвращена | стёрты | остаётся |
| `sudo dnf remove netrulerouter-gui netrulerouter` | остановлена и удалена | возвращена | остаются | остаётся |
| `sudo /usr/libexec/netrulerouter/scripts/uninstall.sh` (архив) | остановлена и удалена | возвращена | остаются | остаётся |
| то же с `--purge` | остановлена и удалена | возвращена | стёрты | остаётся |

«Возвращена» значит, что сеть машины остаётся такой, какой была до
NetRuleRouter: его фильтры пакетов, маршруты и перенаправление DNS сняты.

Данные службы лежат в `/var/lib/netrulerouter` и `/var/log/netrulerouter`.
Журнал аудита в `/var/lib/netrulerouter/audit` — это запись того, что меняло
вашу маршрутизацию, и ни одно удаление его не стирает; удалите эту папку
вручную, когда она станет не нужна. У `rpm` нет аналога `apt purge`; после
`dnf remove` данные стираются вручную:

```bash
sudo find /var/lib/netrulerouter -mindepth 1 -maxdepth 1 ! -name audit -exec rm -rf {} +
sudo rm -rf /var/log/netrulerouter
```

То, что каждый пользователь хранит в своей домашней папке (настройки, кэши),
пакет не трогает никогда; перечень — на странице
[«Где NetRuleRouter хранит свои файлы»](where-files-live.md).

## Службой владеет менеджер пакетов

На машине, где NetRuleRouter поставлен из пакета, службу ставит, обновляет и
удаляет менеджер пакетов. `nrr-cli install`, `uninstall` и `reinstall`, а также
скрипты установки из клона репозитория там отказываются и объясняют почему;
запуск и остановка по-прежнему работают через `nrr-cli start` / `nrr-cli stop`
или `systemctl`.

Если поставить пакет на машину, где служба была установлена из клона или из
архива, пакет забирает эту установку себе: старая служба снимается, её данные
остаются, и на её месте запускается служба из пакета.

## Если пропала сеть

Если служба остановилась так, что машина осталась без сети, верните сеть
командой:

```bash
sudo nrr-cli reset-network --confirm
```

а если консоль недоступна —
`sudo /usr/libexec/netrulerouter/scripts/reset-network.sh`. Подробнее — в
[«Восстановление доступа к сети»](recovering-network-access.md).
