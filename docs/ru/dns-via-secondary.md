# DNS через туннель

[English](../en/dns-via-secondary.md) · **Русский**

Прежде чем компьютер сможет обратиться к сайту, имя сайта нужно
превратить в адрес. Обычно этот запрос идёт к резолверу, который выдал
основной провайдер, и ответ принимается на веру.

Не все провайдеры отвечают честно. Для части имён они возвращают неверный
адрес, пустой ответ или адрес, который никуда не ведёт. Сайт после этого
не открывается — даже если правила маршрутизации верны, а дополнительное
подключение поднято и работает.

Что бы ни стояло в этой настройке, имена из ваших правил для
дополнительного подключения запрашиваются через него, пока оно поднято:
основной провайдер их не видит и не может подменить ответы. Это касается
собственных запросов NetRuleRouter к этим именам, а при локальном
DNS-резолвере (способ маршрутизации по умолчанию) — и запросов ваших
программ к ним.

Настройка добавляет к этому остальные собственные запросы NetRuleRouter:
имена из ваших правил для основного подключения, сайты под вашими
правилами доменов и зон, адреса которых он поддерживает свежими, и
вопросы о том, какому сайту принадлежит адрес. Когда она включена, они
тоже идут через дополнительное подключение.

Остальные запросы ваших программ она не переносит. Когда программа
запрашивает сайт, которого нет ни в одном вашем правиле для
дополнительного подключения, вопрос уходит к резолверу основного
провайдера — включена настройка или нет.

## Что это даёт

- **На сайты, которые вы направляете, отвечает не провайдер.** Имя из
  ваших правил для дополнительного подключения разрешается через него,
  поэтому мёртвый или неверный адрес, который провайдер выдаёт для этого
  имени, до программы не доходит. Для этого настройка не нужна.
- **Когда настройка включена, основной провайдер не видит имён, которые
  NetRuleRouter запрашивает для ваших правил.** Эти запросы уходят через
  дополнительное подключение, как и остальной маршрутизируемый трафик.
- **Маршрутизация не меняется.** Правила срабатывают так же; меняется
  только источник ответов.

## Когда провайдер подменяет имя сайта

Сайт открывается в одном окне браузера и не открывается в другом — чаще
всего работает в обычном окне и не работает в приватном, либо работает в
одном браузере и не работает в другом. Эта разница — сильный признак
того, что дело в разрешении имён, а не в маршрутизации: окно, где всё
работает, переиспользует ранее полученный ответ, а второе спрашивает
заново и получает подменённый.

Видео, которое не воспроизводится, хотя сама страница загрузилась, — та
же история: страница пришла из кэша, а адреса видео-серверов пришлось
запрашивать заново.

Помогает правило, которое отправляет этот сайт через дополнительное
подключение: тогда его имя запрашивается там — с настройкой или без неё.
Если включить настройку без такого правила, то, что программы узнают о
сайте, не изменится.

## Что нужно

Дополнительное подключение должно быть выбрано и поднято. Если оно
недоступно — ещё не подключилось или отвалилось — запросы идут через
основное подключение, чтобы разрешение имён не переставало работать;
пока дополнительное подключение не вернётся, основной провайдер эти
запросы видит. Исключение — сайт, который защита от утечки удерживает,
пока дополнительное подключение лежит: его имя через основное
подключение не запрашивается вовсе.

Настройка работает при любом способе маршрутизации: она меняет то, где
NetRuleRouter спрашивает, а не то, как применяется защита. Её можно
сочетать с посайтовой маршрутизацией через виртуальные адреса (fake-IP)
или использовать отдельно.

## Куда уходят запросы и что провайдер всё же может увидеть

При выключенной настройке имена из ваших правил для дополнительного
подключения идут через него к одному публичному резолверу — Quad9
(149.112.112.112). Quad9 видит эти имена; другие ваши запросы туда не
отправляются, кроме повторного вопроса, описанного ниже.

При включённой настройке все собственные запросы NetRuleRouter идут через
дополнительное подключение к публичным резолверам: 1.1.1.1 (Cloudflare),
8.8.8.8 (Google) и 9.9.9.9 (Quad9). Эти службы видят имена вместо вашего
основного провайдера.

Если основной провайдер отвечает на имя из ваших правил адресом, похожим
на блокировку, NetRuleRouter ещё раз спрашивает об этом одном имени
публичные резолверы выше, чтобы правило всё же получило настоящий адрес.
Этот повторный вопрос идёт тем же путём, что и остальные: через
дополнительное подключение там, где так сказано в двух абзацах выше, и
через основное в остальных случаях (имя из правил для основного
подключения при выключенной настройке или любое имя, пока
дополнительное подключение лежит).

Запрос, на который дополнительное подключение не ответило вовремя,
повторяется через него же. Только когда
дополнительное подключение перестаёт отвечать совсем, запросы
возвращаются на основное, чтобы имена продолжали разрешаться; такие
запросы основной провайдер видит.

## Чего она НЕ делает

- Не шифрует и не анализирует ваш трафик и не меняет, какие сайты куда
  маршрутизируются.
- Не переносит запросы ваших программ к сайтам вне ваших правил для
  дополнительного подключения: они в любом случае идут к резолверу
  основного провайдера.
- Не влияет на запросы, которые браузер делает сам через встроенный
  шифрованный DNS. Если браузер настроен так, его ответы приходят от
  его собственного резолвера и до NetRuleRouter не доходят. Как этот
  случай решается — см.
  [Посайтовая маршрутизация через виртуальные адреса (fake-IP)](fake-ip.md).

## Как включить

Настройки → Поведение маршрутизации → **DNS через туннель**. Переключатель
появляется, когда выбрано дополнительное подключение. По умолчанию выключено; изменение действует сразу и
запоминается между запусками.
