# Браузерное расширение NetRuleRouter

Первая самостоятельная версия для Chromium 120+ и Firefox 128+. Приложение NetRuleRouter для её работы не требуется. Popup позволяет изменить профиль текущего сайта; в настройках доступны общие значения, список профилей и поддерживаемая настройка браузера.

Само открытие расширения не включает изменения. При сохранении языкового профиля расширение запрашивает доступ к выбранному сайту и применяет выбор. Прерванная операция, которую пользователь уже запросил, может продолжиться при следующем запуске фоновой части.

## Что работает

- Языковые профили меняют заголовок запроса `Accept-Language` для HTTP(S)-запросов к выбранным **доменам назначения**. Они не меняют `navigator.language`, `navigator.languages`, JavaScript workers, часовой пояс, язык интерфейса браузера и другие свойства отпечатка. Запросы страницы к сторонним доменам используют профили этих доменов с учётом выданных разрешений.
- Общая настройка языка сохраняет значение браузера или задаёт языковой тег вручную, например `en-US`. Для сайта можно выбрать свой язык либо оставить значение браузера. Явное значение браузера останавливает наследование для этого сайта. Возврат к наследованию удаляет явный профиль сайта: снова действует подходящий более широкий профиль или общая настройка. Более конкретный домен имеет приоритет; охват поддоменов включается отдельно.
- Изменения действуют для следующих запросов. Перезагрузка страницы выполняется только по команде пользователя. Сайт может выбирать язык по cookie, настройкам учётной записи или собственному коду.
- В Chromium доступна явная настройка WebRTC `disable_non_proxied_udp`: расширение объясняет последствия и запрашивает разрешение `privacy`. Настройка применяется ко всему профилю браузера через область `regular`, включая другие вкладки; Chromium может наследовать её в окнах инкогнито. Возможны проблемы со звонками и демонстрацией экрана. Освобождение настройки снимает значение расширения, если оно всё ещё управляет ожидаемым значением. Это не выбирает и не проверяет сетевой маршрут.
- В Firefox управление WebRTC в этой версии выключено: та же настройка иначе работает без настроенного прокси. Расширение не подменяет её более строгим режимом.

Native messaging host и связь с приложением ещё не реализованы. Пока нет выбора языка вслед за маршрутом, часового пояса по маршруту, наследования настроек из NRR и передачи браузерных изменений обратно. Интерфейс показывает самостоятельный режим и ограниченный охват изменения языка.

## Исходники и сборка

| Путь | Назначение |
| --- | --- |
| `src/ui/` | Popup, настройки, список профилей и стили |
| `src/_locales/{en,ru}/` | Переводы расширения |
| `src/controller.js`, `src/background.js` | Интеграция с браузером |
| `policy/` | Rust-код политики и его тесты |
| `manifests/` | Отдельные манифесты Chromium и Firefox |
| `scripts/build.mjs` | Сборка WASM и каталогов расширения |
| `tests/` | Тесты контроллера, переводов и подключения WASM |
| `dist/chromium/`, `dist/firefox/` | Готовые каталоги для загрузки в браузер |
| `policy/target/` | Промежуточные файлы Rust и WASM |

Сборка использует иконки приложения из `assets/icons/app/`. Сгенерированные каталоги исключены из Git. Изменения в `dist/` не меняют исходники.

## Собрать и проверить

Нужны Node.js 22+, Cargo/Rust и цель Rust `wasm32-unknown-unknown`. У JavaScript-пакета нет внешних зависимостей. Выбирая машину для запуска команд, соблюдайте правила репозитория.

Из корня репозитория:

```powershell
rustup target add wasm32-unknown-unknown
npm --prefix apps/browser-extension run build
npm --prefix apps/browser-extension test
cargo test --manifest-path apps/browser-extension/policy/Cargo.toml --target-dir apps/browser-extension/policy/target
```

Сборка должна предшествовать JavaScript-тестам: один из них загружает настоящий WASM-модуль release-сборки. Сборка использует зафиксированные зависимости Rust и проверяет совпадение ключей переводов расширения. Она создаёт оба каталога браузеров, но не подписывает и не публикует расширение.

Те же команды напрямую через Node из `apps/browser-extension/`:

```powershell
node scripts/build.mjs
node --test tests/*.test.mjs
```

## Загрузить для разработки

В Chrome откройте `chrome://extensions`, в Edge — `edge://extensions`. Включите режим разработчика, нажмите **Загрузить распакованное расширение** и выберите `apps/browser-extension/dist/chromium`. После новой сборки обновите расширение на этой странице и заново откройте popup или настройки.

В Firefox откройте `about:debugging#/runtime/this-firefox`, нажмите **Загрузить временное дополнение** и выберите `apps/browser-extension/dist/firefox/manifest.json`. Такая установка действует до закрытия Firefox. После новой сборки нажмите **Перезагрузить** у дополнения. Подписанный пакет эта сборка не создаёт.

## Разрешения и хранение

Обязательные разрешения: `storage`, `activeTab`, `declarativeNetRequestWithHostAccess`. Доступ к сайтам запрашивается отдельно: для изменения сайта — выбранный домен, с охватом поддоменов — соответствующая область, для общего языка вручную — все HTTP(S)-сайты. Управление WebRTC в Chromium отдельно запрашивает необязательное разрешение `privacy`.

Профили хранятся локально, без синхронизации через учётную запись. Если запрошенное изменение не удалось применить или операция прервалась, интерфейс может показать незавершённое применение. Расширение меняет только запрошенные языковые правила и явно выбранную настройку WebRTC.

## Что остаётся для интеграции

- Аутентифицированный native messaging host с версионированным протоколом и поддержка браузерных настроек в приложении.
- Согласованные с NRR приоритеты общих настроек, маршрутов и сайтов, доступные возможности, область разрешённых изменений и возврат правок в приложение.
- Контроль актуальности соединения, поведение без связи и подтверждённое состояние маршрута до включения режима следования за ним.
- Поддерживаемый механизм часового пояса с понятным охватом документов, фреймов и workers до появления такого управления.
- Подписание пакетов и распространение.
